# Как протестировать «Учебные программы» (сторис 009–019)

Для Алекса и Мурада. Идём по ролям: Мурад в админке, ученик на сайте, потом Мурад смотрит прогресс.
Время: ~60–90 минут. Отмечайте ✅/❌ и пишите, что увидели.

## 0. Подготовка

| Что                | Где                                                                                                |
| ------------------ | -------------------------------------------------------------------------------------------------- |
| Preview (с демо)   | ссылка Vercel Preview ветки; демо-ученица Anna входит на `DEMO_STUDENT_EMAIL`                      |
| Production (чисто) | основной домен; данных нет, тестируем на реальной почте                                            |
| Вход               | всегда по коду из письма (пароля нет). Письма идут с `login@mail.growtomiddle.dev`, проверьте спам |
| Два браузера       | обычное окно = Мурад, приватное окно = ученик (иначе сессии перемешаются)                          |

**Совет:** сначала пройдите всё на Preview (там уже есть данные и письма «глушатся» для демо-учеников), потом коротко повторите на Production на реальных данных.
Тестового ученика на Production заведите на отдельный адрес (например `you+student1@gmail.com`).

## Часть A. Мурад в админке (`/admin`)

### A1. Типы занятий и программа (009)

1. **Типы занятий** → создать «Anki», минимум 20 мин. Ожидаем: сохранилось.
2. Создать тип с минимумом `0` и `241` → ошибка «диапазон 1–240».
3. **Программы** → создать «A2→B1», 52 недели, статус `draft`; день 1 = [Anki 20, Сериал 40], день 4 пустой. Ожидаем: 7 дней шаблона.
4. Уровень «с» = B2, «до» = B1 → ошибка «Начальный уровень должен быть ниже целевого».
5. В день добавить 6-е занятие → «В дне не больше 5 занятий».
6. Две программы с одинаковым адресом (slug) → «Такой адрес уже занят».
7. Попробовать удалить тип, который уже в программе → отказ «Тип используется в программах: …».

### A2. Банк заданий и план по умолчанию (010)

1. **Банк заданий** → задание уровня B1 «Отзыв на серию» с текстом.
2. В программе открыть «План по умолчанию», поставить задание на неделю 1, день 5. Видна сетка неделя × день.
3. «Копировать неделю 1 в недели 2–4»: создаются задания, уже существующие не перезаписываются, показан итог.
4. Задание уровня A1 в программу B1→B2 → ошибка «уровень вне программы».
5. 4-е задание в день → «Не больше 3 заданий». Неделя 53 / день 8 → ошибка диапазона.
6. Сократить длительность с 52 до 40 недель при заданиях в неделях 41–52 → отказ.
7. Править текст задания из банка: видна подсказка «Изменения попадут только в новые планы».

### A3. Приглашение ученика (011)

1. **Ученики/Пользователи** → добавить ученика (роль student). Ожидаем письмо-приглашение.
2. Удаление ученика требует подтверждения (проверьте на тестовом, не на реальном).

### A4. Назначение программы (012, 018)

1. На странице ученика: результат теста (IELTS 4.5, CEFR A2, дата), опубликованная программа → сохранить. Статус `assigned`, приходит письмо о назначении (кроме демо).
2. Черновая программа в списке выбора **не** предлагается.
3. Назначить вторую программу тому же ученику → «У ученика уже есть программа».
4. IELTS 9.5 / 4.3, TOEFL 121, дата теста в будущем → ошибки с названием поля.
5. Тест «Мурад (CEFR)» → поле балла скрыто. Уровень теста выше программы → предупреждение, но сохранить можно.
6. Открыть «План ученика»: задания помечены «из пула»; заменить задание на неделе 3, день 2 своим текстом → пометка «своё». План по умолчанию у других не меняется.
7. 4-е задание в день у ученика → ошибка. Удалить задание в прошедшем дне → отметки и комментарий дня остаются.

## Часть B. Ученик (приватное окно, `/login`)

### B1. Вход (011)

1. Ввести неприглашённый email → то же нейтральное сообщение, что и для приглашённого.
2. Приглашённый email → код → попадаем на `/study`.
3. Неверный код 5 раз → «Код устарел, запроси новый». 4 запроса кода за 15 минут → «Слишком много попыток».
4. Ученик открывает `/admin` → его перекидывает на `/study`.
5. `/study/settings` → «Обращаться на „вы“» → тексты переключились на «вы». На английском тексты не меняются.
6. Без входа открыть `/study` → редирект на `/login`.

### B2. Начало программы (012)

1. Ученик без программы: «Мурад назначит программу после теста уровня».
2. Назначена программа: карточка с уровнем, длительностью, результатом теста. «Начать» → подтверждение → открывается «Сегодня», день 1.
3. Дважды быстро нажать «Начать» → старт один раз. Часовой пояс по умолчанию Алматы, можно сменить.

### B3. «Сегодня» и неделя (013)

1. Шапка: «День X из N · Неделя Y», три числа прогресса.
2. Список занятий дня (название, «минимум N мин») и задания.
3. Сетка недели: маркеры ✓ ½ ✕ ‖ — ● (не только цвет). Тап по прошедшему дню показывает его только для чтения.
4. «Все недели»: текущая подсвечена, будущая неделя открывается только для чтения.
5. День отдыха → «Сегодня отдых». Телефон 360 px: нет горизонтального скролла.

### B4. Таймер (014)

1. «Старт» → идёт mm:ss. Закрыть вкладку, открыть через несколько минут → время верное (считает сервер).
2. Достичь минимума (для проверки создайте занятие с минимумом 1 мин) → звук один раз, вибрация, «Минимум выполнен ✓».
3. «Стоп» на середине → «25 из 40 мин», следующий старт продолжает.
4. Старт на втором занятии → первое остановилось и сохранилось. Двойной тап → одно действие.
5. Звук заблокирован браузером → баннер «Минимум выполнен»; кнопка «Проверить звук» работает.

### B5. Ручные отметки (015)

1. «Отметить вручную» 30 мин → сохранено; выполнено, если ≥ минимума.
2. Пропущенный день (✕): отметить все занятия → ✓, часть → ½.
3. Повторная отметка обновляет запись, а не дублирует. `0` сбрасывает, `601` → «Не больше 600 минут».
4. Будущий день и день до старта → кнопок нет.

### B6. Комментарии (016)

1. Написать комментарий к дню, сохранить, обновить — текст на месте. Сохранить пустой → удаляется.
2. 1001 символ → «Не больше 1000 символов». У будущего дня поля нет.

### B7. Пауза (017)

1. «Пауза» + подтверждение → «На паузе с … · День N». Занятия и таймер недоступны.
2. В сетке дни паузы со значком ‖ и не считаются пропусками.
3. «Продолжить» → день программы тот же, что до паузы. Пауза и возобновление в один день не оставляют следа.

## Часть C. Мурад смотрит прогресс (019)

1. Войти владельцем и открыть `/ru/study/students` (ссылки в шапке нет, только по адресу).
2. Список: у каждого имя, программа, статус, «день X из N», сделано/пропущено, минуты, последний учебный день. У ожидающего старта только статус.
3. Открыть ученика: сетка текущей и прошлой недели (только чтение, ничего не кликается) и последние комментарии, новые сверху, с датой и днём программы.
4. Ученик открывает `/study/students` → «страница не найдена». Аноним → на вход, потом назад на страницу.
5. Чужой/выдуманный id → «не найдено». Пустые состояния: нет учеников / нет комментариев.
6. Страница ничего не меняет: после просмотра у ученика не появились занятия и комментарии. Приватная заметка по результату теста не видна.
7. Телефон 360 px читается.

## Приложение. Как создать челлендж 90–90–1 (сторисы 005–008)

Отдельно от учебных программ. Страница челленджа публичная и работает по адресу `/challenge/<slug>`.

1. Войти в `/admin` (код из письма) → **Challenges** → **Create New**.
2. Заполнить поля:
   - **Title**: название (отдельно для ru и en, переключатель языка наверху).
   - **Slug**: латиница, цифры и дефисы, например `90-90-1`. Это адрес страницы: `/challenge/90-90-1`.
   - **Start date**: день 1; **Time zone**: по умолчанию `Asia/Almaty`, день меняется в местную полночь.
   - **Duration / Daily minutes / Block length**: 90 / 90 / 15 по умолчанию. Длительность должна делиться на длину блока.
   - **Videos**: ровно по одному видео на блок (90 / 15 = 6 штук). У каждого название, по желанию ссылка YouTube, дата публикации и ретро (что сработало, что нет, что менять).
   - **Rules**: правила (что считается, что нет). Если пусто, раздел скрыт.
   - **Is public** (справа): **включить, иначе страница отдаёт «Страница не найдена»**.
3. Сохранить и открыть `/challenge/90-90-1` (или `/en/challenge/90-90-1`).

### Что проверить

| Что                     | Ожидание                                                                                                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сетка                   | 90 клеток, 6 блоков по 15 с названиями видео, состояния закрыт / сегодня / пропущен / впереди не только цветом                                                                            |
| Прогресс                | минуты (например «270 / 8 100 мин»), видео (x / 6), сессии, «Осталось N дней»                                                                                                             |
| Закрыть день (007)      | под Мурадом (вход в админку) тап по сегодняшней или прошлой клетке → минуты (по умолчанию 90) и заметки до 500 символов → день закрыт; повторно обновляет запись, будущий день недоступен |
| Без входа               | клетки только для чтения, видна дата, минуты и заметки закрытых дней                                                                                                                      |
| Не начался / закончился | «Начало …» / «Челлендж завершён», клетки «сегодня» нет                                                                                                                                    |
| Ретро (008)             | форма ретро по видео доступна Мураду, остальным только чтение                                                                                                                             |
| Ошибки                  | 3-й день в `Slug` с заглавными буквами, число видео не равно 90 / 15, длительность не делится на блок → понятная ошибка; удалить челлендж с закрытыми днями нельзя                        |

> Ссылка «Челлендж» в шапке сайта ведёт на `/challenge`, а такой страницы нет, поэтому показывается «Страница не найдена».
> Это известная проблема: открывайте `/challenge/<slug>` напрямую (либо ссылку нужно переделать на slug или редирект).

## Известные особенности (не баги)

- Открытие страниц `/study/...` и `/study/students` с «не найдено» отдаёт HTTP 200 (страницы стримятся), это нормально.
- Демо-ученики на Preview не получают писем (`skipEmail`); на Production письма реальные.
- Тестовое демо создаётся только на Preview и никогда на Production.
- Админка: нет ссылки на `/study/students`, страницу открывают по адресу.
